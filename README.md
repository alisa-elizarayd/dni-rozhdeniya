# Дни рождения

Доступное PWA для дней рождения близких: крупный шрифт, спокойный интерфейс, добавление, изменение и удаление записей, локальное сохранение и работа без интернета после первого успешного открытия.

Техническое имя репозитория `dni-rozhdeniya` согласовано с владельцем, поскольку GitHub принимает только ASCII в имени. Русское название сохранено в приложении и manifest.

## Как пользоваться

1. Введите имя, день и месяц. Год можно ввести вручную: тогда карточка покажет возраст в ближайший день рождения. Поле необязательное, старые записи сохраняются.
2. Записи автоматически сортируются по ближайшему дню рождения.
3. Нажмите «Скачать для календаря», импортируйте .ics в календарь и проверьте разрешения и уведомления на телефоне.
4. Сохраните резервную копию JSON. Загрузка копии добавляет недостающие записи по сочетанию имени и даты, включая год.

На iPhone: Safari → Поделиться → На экран Домой. На Android: меню браузера → Установить приложение. Для PWA нужен HTTPS (localhost разрешён для разработки). Открытие index.html как file:// не заменяет установку сайта.

## Честно об уведомлениях

**Автоматических фоновых push-уведомлений в этой статической версии нет.** Service Worker кеширует приложение, но не является постоянно работающим таймером. Браузер может остановить его. GitHub Pages не запускает серверный планировщик.

Рабочая альтернатива — импорт событий в системный календарь. Экспорт создаёт отдельные события на 20 ближайших дней рождения, с 09:00 до 14:00 по местному времени. Если год рождения указан, заголовок содержит его и возраст для соответствующего года. В режиме для iPhone (по умолчанию) создаются основное событие с уведомлением в 09:00 и два дополнительных пятиминутных события с уведомлениями в 11:00 и 13:00. Без галочки создаётся одно событие с тремя VALARM (PT0S, PT2H, PT4H относительно начала). Возраст не фиксируется навсегда в заголовке повторяющейся серии. По окончании 20-летнего горизонта нужен новый экспорт. Поддержка импортированных VALARM зависит от календаря: проверьте время, разрешения и напоминания на реальном телефоне; при необходимости установите их вручную. На Google Calendar импорт файлов выполняется в веб-версии на компьютере. На iPhone возможности открытия .ics зависят от приложения; можно импортировать через календарь на компьютере с синхронизацией на телефон.

Это снимок данных, не подписка и не синхронизация. Изменение или удаление записи в PWA не меняет календарь. Повторный импорт может создать дубликаты. Перед переходом с прежнего экспорта удалите старые ежегодные серии этого приложения. Рекомендуется отдельный календарь для импорта. 29 февраля в невисокосные годы переносится на 28 февраля при генерации конкретных дат.

Для настоящих Web Push нужны сервер, планировщик, хранение подписок и безопасный VAPID-ключ на сервере. На iPhone Web Push поддерживается для приложений на экране «Домой» начиная с iOS 16.4. Разрешение запрашивают по действию пользователя. Доставка зависит от сети и настроек ОС, точная минута не гарантируется.

Источники: [WebKit: Web Push on iOS](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/), [Chromium: жизненный цикл Service Worker](https://chromium.googlesource.com/chromium/src/+/main/docs/security/service-worker-security-faq.md).

## Данные и приватность

Имена и даты остаются в localStorage браузера; аналитики, внешних шрифтов и сторонних скриптов нет. Браузер и установленное приложение могут иметь разные хранилища. Очистка данных сайта, приватный режим или смена телефона могут привести к потере записей. Регулярно сохраняйте JSON-копию. Экспортированный календарь передаёт записи выбранному вами приложению календаря. При повреждённом хранилище запись отключается, чтобы не перезаписать данные.

## Файлы и запуск

`index.html`, `style.css`, `app.js`, `core.js`, `manifest.json`, `sw.js`, `icons/`. Нет сборки и зависимостей. Локальный запуск: `python3 -m http.server 8765` из этой папки, затем http://localhost:8765.

GitHub Pages: Settings → Pages → Deploy from a branch → main → /(root). Все пути относительные, поэтому сайт работает в подпапке репозитория.

При обновлении файлов увеличьте версию CACHE в sw.js. Новая версия активируется после закрытия старых окон приложения; кеши других приложений не удаляются.

## Проверка

Проверены синтаксис JS, невозможные даты, 29 февраля, переход года, день рождения сегодня, строки и правила ICS. Браузерная проверка и результат публикации описаны в VERIFY.md. Проверка уведомлений и установки на физическом iPhone/Android требует устройства пользователя.
